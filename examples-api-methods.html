7. Booking desk — confirm & lock (scoped read-only)

Freeze user interaction while keeping the value readable (unlike disabled, which greys the input out). Each day shows its nightly rate as a badge (via getDateMetadataCallback, the same pricing model as the Dynamic Calculation badges demo). The flow: the guest picks a range, hits Book in the calendar's own action bar, the app calls the server, and on success the range is locked and the button flips to Amend so the confirmed dates can't change until the guest amends. The summary shows a client-side estimate (sum of the badges) while selecting, then the server's real price — which may land a little higher or lower — once confirmed. Locking is scoped — freeze everything, or just some of four aspects (selection · navigation · actions · open). The programmatic API is never gated; only the end user is.

Inline range picker

Drive the lock

Pick a range — the summary shows a live estimate (the sum of the on-screen badges). Then hit Book in the calendar's action bar: a mock server round-trip returns the real price (which can land a bit higher or lower than the estimate) plus a reference code, the confirmed dates lock (🔒 read-only), and the button flips to Amend. Try clicking a day or dragging an endpoint — nothing moves; only Amend stays live (the actions aspect is left unlocked on purpose). Amend releases the lock and drops back to the estimate.

Or a partial lock — freeze the range & buttons but keep the < > arrows live so the guest can still look around:

Status: unlocked · fully interactive 
const picker = document.getElementById('picker-9');

// Nightly-rate badges — same getDateMetadataCallback as the
// "Dynamic Calculation" demo (examples-badges-tooltips.html).
picker.getDateMetadataCallback = ({ date }) => {
    const price = nightlyRate(date);            // your pricing model
    return { badgeText: `$${price}`, badgeClass: `badge-number ${priceTier(price)}` };
};

// Estimate: the picker's own summary sums the on-screen badges for any
// selected range (shows live, including drag preview).
picker.formatSummaryCallback = ({ startDate, endDate }) => {
    if (!startDate || !endDate) return '';
    return `<b>Estimated</b> — ~$${bookingTotal({ start: startDate, end: endDate })}`;
};

// The calendar's own action bar drives the flow. `actionButtons` REPLACES the
// built-in buttons, so we express Clear as a preset and Book as a custom action.
// Booking confirms + locks; amending releases. Swapping the array re-renders the
// bar, so Book ⇄ Amend is just two arrays.
const bookActions  = [{ action: 'clear', text: 'Clear' },
                      { action: 'custom', text: 'Book', onClick: bookNow }];
const amendActions = [{ action: 'custom', text: 'Amend', onClick: amendNow }];

async function bookNow() {
    const { selectedStartDate: start, selectedEndDate: end } = picker;
    if (!start || !end) return;                 // plain range → start/end pair
    const range = { start, end };
    const estimate = bookingTotal(range);       // sum of the nightly badges
    picker.showLoader('calendar');
    const { code, real } = await sendToServer(range, estimate);  // your API call
    picker.hideLoader('calendar');
    const diff = real - estimate;
    picker.showSummary(`<b>Confirmed</b> — $${real} (est. $${estimate}, ${diff >= 0 ? '+' : '-'}$${Math.abs(diff)}) · code ${code}`);
    // Lock everything the guest can touch — but NOT 'actions', so the Amend
    // button we're about to show stays clickable.
    picker.lock(['selection', 'navigation', 'open']);
    picker.actionButtons = amendActions;        // Book → Amend
}

function amendNow() {
    picker.unlock();                            // release every aspect
    picker.hideSummary();                       // drop the confirmed price → re-derive the estimate
    picker.actionButtons = bookActions;         // Amend → Book
}

picker.actionButtons = bookActions;             // start in "Book" mode

// Scoped lock: freeze the range + buttons but let the user
// still browse other months with the < > arrows.
picker.lock(['selection', 'actions']);

// Release it all (or a subset)
picker.unlock();                // everything
picker.unlock('selection');     // just one aspect

// Declarative full lock via attribute / property
// <web-daterangepicker readonly></web-daterangepicker>
picker.readonly = true;
picker.lockedAspects;           // -> ['selection','navigation','actions','open']
void lock(aspects?: LockAspect | LockAspect[])
void unlock(aspects?: LockAspect | LockAspect[])
void toggleLock(aspects?: LockAspect | LockAspect[])
boolean isAspectLocked(aspect: LockAspect)

boolean readonly

8. Confirm & close — validate before dismissing (floating)

A custom Confirm button that runs your own logic before the calendar closes. A custom action button never auto-closes the picker, so the callback is fully in control: when the selection is invalid it calls showMessage(…) and returns — the calendar stays open with the warning — and only when the selection passes does it call apply(), which commits the value and closes. Paired with commit-mode="manual" so a bare day click can't dismiss the picker before the guest reaches the gate and no built-in Apply button renders — Confirm is the only commit path. This example requires a range of at least 3 nights. The onClick is awaited, so the same shape works against an async/server check.

Floating range picker

Status: nothing confirmed yet

What to try

Open the calendar and hit Confirm with no selection — you get a warning and the calendar stays open. Pick a 1–2 night range and confirm — it warns that the minimum is 3 nights and stays open. Pick 3+ nights and confirm — the value commits, the calendar closes, and the status line below updates. 

<web-daterangepicker id="picker" selection-mode="range"
                     commit-mode="manual"></web-daterangepicker>

const picker = document.getElementById('picker');
const MIN_NIGHTS = 3;

// A custom button never auto-closes — the callback decides. onClick is awaited,
// so you can validate against a server too.
picker.actionButtons = [
    { action: 'clear', text: 'Clear' },
    {
        action: 'custom',
        text: 'Confirm',
        cssClass: 'drp__button--apply',              // primary-action accent
        onClick: async ({ picker }) => {
            const start = picker.selectedStartDate;
            const end   = picker.selectedEndDate;

            // 1) nothing / half a range → warn, stay open
            if (!start || !end) {
                picker.showMessage('Please select a full date range first.', 'error');
                return;
            }
            // 2) business rule → warn, stay open
            const nights = Math.round((end - start) / 86400000);
            if (nights < MIN_NIGHTS) {
                picker.showMessage(`Minimum ${MIN_NIGHTS} nights — you picked ${nights}.`, 'warning');
                return;
            }
            // 3) valid → commit AND close
            picker.hideMessage();
            picker.apply();
        }
    }
];
void showMessage(html: string, type?: 'error' | 'warning' | 'info' | 'success', autoHideMs?: number)
void hideMessage()
void apply()
void hide()

React/Vue Integration

// React
import { useRef, useEffect } from 'react';

function DatePicker({ value, onChange }) {
    const pickerRef = useRef(null);

    useEffect(() => {
        const picker = pickerRef.current;

        const handleSelect = (e) => {
            onChange(e.detail.formattedValue);
        };

        picker.addEventListener('date-select', handleSelect);
        return () => picker.removeEventListener('date-select', handleSelect);
    }, [onChange]);

    useEffect(() => {
        if (pickerRef.current && value) {
            pickerRef.current.setInputValue(value);
        }
    }, [value]);

    return <web-daterangepicker ref={pickerRef} />;
}

// Vue 3
<template>
    <web-daterangepicker
        ref="picker"
        @date-select="handleSelect"
    ></web-daterangepicker>
</template>

<script setup>
import { ref, watch } from 'vue';

const picker = ref(null);
const selectedValue = ref('');

function handleSelect(event) {
    selectedValue.value = event.detail.formattedValue;
}

watch(selectedValue, (newValue) => {
    if (picker.value) {
        picker.value.setInputValue(newValue);
    }
});
</script>

State Synchronization

// Synchronize with application state
class DateRangeManager {
    constructor() {
        this.picker = document.getElementById('date-range');
        this.state = {
            start: null,
            end: null,
            formatted: ''
        };

        this.init();
    }

    init() {
        // Listen for picker changes
        this.picker.addEventListener('date-select', (e) => {
            if (e.detail.dateRange) {
                this.state.start = e.detail.dateRange.start;
                this.state.end = e.detail.dateRange.end;
                this.state.formatted = e.detail.formattedValue;
                this.onStateChange();
            }
        });

        // Restore state on page load
        this.restoreState();
    }

    onStateChange() {
        // Update UI, save to localStorage, sync with server, etc.
        localStorage.setItem('date-range', JSON.stringify({
            start: this.state.start?.toISOString(),
            end: this.state.end?.toISOString()
        }));

        this.updateDashboard();
    }

    restoreState() {
        const saved = localStorage.getItem('date-range');
        if (saved) {
            const { start, end } = JSON.parse(saved);
            this.picker.selectedRanges = [{
                start: new Date(start),
                end: new Date(end)
            }];
        }
    }

    updateDashboard() {
        // Update other UI elements based on date range
        console.log('Updating dashboard for:', this.state);
    }
}
