TH01 · Overview: How CSS Variable Theming Works

✅ Shadow DOM + CSS Variables = Powerful Theming

This component uses :host to define CSS variables inside the shadow DOM. This means:
  • Variables are accessible to component styles
  • You can override them from your page CSS
  • Each instance can have a different theme
/* Your page CSS */ web-daterangepicker.theme-green { --drp-accent-color: #10b981; --drp-accent-color-hover: #059669; }

Open any picker to compare how identical content renders under each theme. Time-picker examples intentionally show no calendar data.

TH08 · Classifier Retheming (dayClass / badgeClass conventions)

The picker ships default styling for five consumer-data class names (dayClass: 'holiday' | 'event' and badgeClass: 'badge-number' | 'badge-count' | 'badge-text'), each backed by overridable CSS variables. Set dayClass / badgeClass on your data; override the variables on the host to recolor every day or badge using that classifier. No customStylesCallback required — the rules already exist in shipped CSS.

✓ All three pickers receive the same specialDates data; only the variable overrides differ.
/* Override on the host element — every day/badge using that classifier repaints. */ web-daterangepicker.theme-classifier-corporate { --drp-holiday-color: #475569; /* slate instead of red */ --drp-event-color: #0ea5e9; /* sky blue instead of green */ --drp-badge-number-bg: #0ea5e9; --drp-badge-count-bg: #475569; --drp-badge-text-bg: #64748b; } /* All twelve classifier variables you can override: */ --drp-holiday-color, --drp-holiday-bg-opacity, --drp-holiday-hover-bg-opacity --drp-event-color, --drp-event-bg-opacity, --drp-event-hover-bg-opacity --drp-badge-number-bg, --drp-badge-number-color --drp-badge-count-bg, --drp-badge-count-color --drp-badge-text-bg, --drp-badge-text-color
Custom classifier names (e.g., dayClass: 'salsa') live outside this convention — you ship the CSS via customStylesCallback instead. See the Badges & Tooltips examples for the custom-classifier demo.

TH09 · Time Picker Theming (all four UIs)

All four time UIs — rolls, clock, wheel, compact — consume the same --drp-accent-color token used elsewhere. Selected hour/minute, the clock hand, the AM/PM toggle, the wheel's center selection band, the compact pill backgrounds and focus ring — all follow it automatically. No display-specific overrides needed for color theming.

✓ Accent, background, border, and text-on-accent tokens cascade into all four time pickers without extra overrides.
For fine-grained control, override the time/clock-specific tokens directly — e.g., --drp-clock-hand-color for a different hand color than the accent, --drp-clock-face-bg for the dial background, --drp-time-picker-label-color for the column headers, etc. See the variable list below.
How sizing works: The calendar uses --drp-rem (default: 10px) as a base unit. All spacing, fonts, and sizes derive from this. Change --drp-rem to scale everything proportionally, or override individual CSS variables for fine-grained control.
Shadow DOM Note: CSS variables must be set directly on the <web-daterangepicker> element (via inline style or CSS selector), not on a wrapper div. This is because the component uses Shadow DOM.

TH10 · Global Scaling via --drp-rem

Scale the entire calendar by setting --drp-rem directly on the element. Default is 10px.

Perfect for dense dashboards
Good for compact layouts
Standard size

/* Option 1: CSS class targeting the element */ web-daterangepicker.scale-sm { --drp-rem: 8px; } /* Option 2: Inline style */ <web-daterangepicker style="--drp-rem: 8px"> /* Option 3: ID selector */ #my-calendar { --drp-rem: 15px; }

TH15 · Time Picker — Scaling

The picker-mode="time" rolling lists derive their column width, item height, padding, and font size from --drp-rem (and the spacing/font tokens it drives). Change --drp-rem and the whole time picker scales.

4 columns (H, M, S, AM/PM) scale together

TH16 · Datetime Picker — Scaling

picker-mode="datetime" places the calendar and the time rolls side by side. The popover floor (--drp-datetime-min-width, default calc(56 * var(--drp-rem))) scales with --drp-rem so the side-by-side layout holds at any scale. Inline mode skips the floor and sizes to content.

Spacing and font overrides flow through to the time rolls too

TH17 · Clock Picker — Scaling

time-display="clock" uses a fixed-aspect dial. All clock metrics (dial size, ring radii, number-button diameter, hand pivot) derive from --drp-rem via calc(), so the whole face scales proportionally without breaking the angle math.

Calendar + clock side by side, both scaled together

TH18 · Wheel Picker — Scaling

time-display="wheel" is an iOS-style barrel of snap-scrolling columns. The center band height, item height, and fade gradients all derive from --drp-rem, so all three sizes feel identical at their respective scales.

Calendar + wheel barrel side by side

TH19 · Compact Picker — Scaling

time-display="compact" is iOS 14+ pills. The pill size, padding, and AM/PM toggle scale with --drp-rem so the row stays proportionate to the surrounding input.

Calendar + compact pills side by side

TH22 · Responsive Sizing

Use media queries targeting the element to scale based on viewport:

8px on mobile, 10px on tablet, 12px on desktop
/* Responsive scaling with media queries */ @media (max-width: 768px) { web-daterangepicker.responsive-calendar { --drp-rem: 8px; } } @media (min-width: 769px) and (max-width: 1200px) { web-daterangepicker.responsive-calendar { --drp-rem: 10px; } } @media (min-width: 1201px) { web-daterangepicker.responsive-calendar { --drp-rem: 12px; } }
