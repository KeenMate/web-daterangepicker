🐛 Logging & Debugging

Built-in logging system with categorized debug output for development and troubleshooting

Overview: Built-in Logging System

Built-in categorized logging

The date picker includes a comprehensive logging system provided by @keenmate/web-components-core. Logs are grouped into colour-coded DRP:* categories and easy to filter for troubleshooting.
⚠️ Development Only
Debug logging is for development only. Never ship with show-debug-info enabled in production!

Log Categories

The logging system organizes output into 8 categories. In the console each line is prefixed with the full category name — DRP:GENERAL, DRP:UI, etc. (the short badge below is just the suffix):

Category Badge What It Logs
DRP:GENERAL GENERAL General/initialization, option parsing, setup
NAVIGATION NAVIGATION Month navigation, keyboard navigation
UI UI Show/hide calendar, positioning, visibility changes
RENDERING RENDERING Calendar rendering, day cell updates, DOM operations
SELECTION SELECTION Date selection, range selection, value changes
VALIDATION VALIDATION Date validation, disabled date handling, range validation
DRAG DRAG Drag-to-adjust functionality, drag previews
INTERACTION INTERACTION User interactions, clicks, hover events

Example 1: Basic Logging

Enable debug logging with the show-debug-info attribute:

<date-range-picker selection-mode="single" show-debug-info> </date-range-picker>
✅ Open your browser console (F12) and click the input to see initialization and UI logs

Expected console output:

[DRP:GENERAL] Week starts on day: 1 [DRP:GENERAL] Creating calendar [DRP:RENDERING] renderCalendar() called [DRP:UI] show() - adding visible class [DRP:UI] Positioning calendar [DRP:RENDERING] Rendering month 0: November 2025

Filtering Console Logs

Use browser console filters to focus on specific categories:

Filter by Category

// In browser console filter box: DRP:GENERAL // Only general/initialization logs DRP:VALIDATION // Only validation logs DRP:SELECTION // Only selection logs DRP:DRAG // Only drag logs DRP: // All categories

Filter by Function

// Filter by function name: renderCalendar // Only calendar rendering validateRange // Only range validation selectDate // Only date selection

Programmatic Control

// Logging is controlled globally (not per-element), via the component's // entry on window.components — or the named module exports. const { logging } = window.components['web-daterangepicker']; logging.enableLogging(); // all categories → debug logging.setLogLevel('error'); // all categories → errors only logging.disableLogging(); // silence everything logging.setCategoryLevel('DRP:UI', 'debug'); // one category (bare 'UI' also works) // Equivalent named imports: // import { enableLogging, setLogLevel, setCategoryLevel } from '@keenmate/web-daterangepicker';

Log Message Format

Each log line is prefixed with its colour-coded category, followed by the message:

[DRP:CATEGORY] Message with context Example: [DRP:GENERAL] Week starts on day: 1 │ │ │ └─ Message with details └─────────────── Category label (DRP:GENERAL, DRP:UI, …), colour-coded per category

Best Practices

  • Development: Enable show-debug-info when troubleshooting
  • Production: Always remove show-debug-info attribute
  • Performance: Logs are minimal overhead when disabled
  • Filtering: Use console filters to reduce noise
  • Categories: Focus on specific categories for targeted debugging (filter on DRP:)

Complete Example

<!-- HTML with debug enabled --> <web-daterangepicker selection-mode="range" visible-months-count="2" disabled-weekdays="0,6" disabled-dates-handling="block" show-debug-info> </web-daterangepicker> <script> // Listen to events and log details const picker = document.querySelector('web-daterangepicker'); picker.addEventListener('date-select', (e) => { console.log('Date selected event:', e.detail); }); // Programmatic logging control setTimeout(() => { // Disable logging after 30 seconds window.components['web-daterangepicker'].logging.disableLogging(); console.log('Debug logging disabled'); }, 30000); </script>
