EVENTS & CALLBACKS
==================

EVENT SYSTEM
------------
Date picker fires custom events on selection.

TWO EVENT NAMES (identical data)
---------------------------------
1. date-select - Primary event
2. change - Alias event (for compatibility)

Both fire simultaneously with same data.
Use whichever fits your naming convention.

LISTENING TO EVENTS
-------------------
Web Component:

const picker = document.querySelector('web-daterangepicker');

picker.addEventListener('date-select', (event) => {
  console.log('Selected:', event.detail);
});

// Or use 'change' alias
picker.addEventListener('change', (event) => {
  console.log('Changed:', event.detail);
});

Events bubble and are composed (cross Shadow DOM).

SINGLE MODE EVENT DATA
----------------------
event.detail structure:

{
  date: Date object,
  formattedValue: "2025-11-17"
}

Example:
picker.addEventListener('date-select', (event) => {
  const { date, formattedValue } = event.detail;

  console.log('Date object:', date);
  console.log('Formatted:', formattedValue);
  console.log('Day of week:', date.getDay());
});

RANGE MODE EVENT DATA
---------------------
event.detail structure:

{
  dateRange: { start: Date, end: Date },
  formattedValue: "2025-11-17 - 2025-11-24"
}

Example:
picker.addEventListener('date-select', (event) => {
  const { dateRange, formattedValue } = event.detail;

  console.log('Start:', dateRange.start);
  console.log('End:', dateRange.end);
  console.log('Formatted:', formattedValue);

  const nights = Math.floor(
    (dateRange.end - dateRange.start) / (1000 * 60 * 60 * 24)
  );
  console.log('Nights:', nights);
});

RANGE WITH DISABLED DATES HANDLING
-----------------------------------
When using disabled-dates-handling modes, additional data:

Mode: 'allow'
{
  dateRange: { start, end },
  formattedValue: "...",
  enabledDates: [Date, Date, ...],     // Enabled dates in range
  disabledDates: [Date, Date, ...],    // Disabled dates in range
  getEnabledDateCount: () => number,   // Helper function
  getTotalDays: () => number           // Helper function
}

Mode: 'split'
{
  dateRanges: [
    { start: Date, end: Date },
    { start: Date, end: Date }
  ],
  dates: [Date, Date, ...],  // All enabled dates
  formattedValue: "..."
}

Mode: 'individual'
{
  dates: [Date, Date, ...],  // All enabled dates
  formattedValue: "..."
}

Example (allow mode):
picker.addEventListener('date-select', (event) => {
  const { dateRange, enabledDates, disabledDates } = event.detail;

  console.log('Range:', dateRange);
  console.log('Enabled:', enabledDates.length, 'dates');
  console.log('Disabled:', disabledDates.length, 'dates');
  console.log('Total:', event.detail.getTotalDays(), 'days');
});

MULTIPLE MODE EVENT DATA
------------------------
event.detail structure:

{
  dates: [Date, Date, ...],          // Selected individual dates
  dateRanges: [{ start, end }, ...], // Selected ranges
  formattedValue: "..."
}

Example:
picker.addEventListener('date-select', (event) => {
  const { dates, dateRanges } = event.detail;

  console.log('Individual dates:', dates.length);
  console.log('Ranges:', dateRanges.length);
});

CUSTOM-ACTION EVENT
-------------------
Fired when any button with data-action="custom" is clicked.
Works for both action buttons and message buttons.

Event detail contains all data-* attributes (except data-action) as camelCase keys.

LISTENING TO CUSTOM-ACTION
--------------------------
picker.addEventListener('custom-action', (e) => {
  console.log(e.detail);
  // { startDate: '2026-01-14', endDate: '2026-01-17', ... }
});

USE IN MESSAGE BUTTONS
----------------------
Display alternative date options in messages:

picker.showMessage(`
  <button data-action="custom"
          data-start-date="2026-01-14"
          data-end-date="2026-01-17"
          data-nights="3">
    Jan 14 - Jan 17 (3 nights)
  </button>
`);

picker.addEventListener('custom-action', (e) => {
  const { startDate, endDate, nights } = e.detail;

  if (startDate && endDate) {
    picker.selectedRanges = [{
      start: new Date(startDate),
      end: new Date(endDate)
    }];
    picker.hideMessage();
  }
});

USE IN ACTION BUTTONS
---------------------
Custom action buttons with data attributes:

picker.actionButtons = [
  {
    action: 'custom',
    text: 'Last 7 Days',
    onClick: (picker) => {
      // onClick still works for backward compatibility
    }
  }
];

// But prefer using the event for consistency:
picker.addEventListener('custom-action', (e) => {
  // Handle all custom actions in one place
});

DATA ATTRIBUTE CONVERSION
--------------------------
HTML data-* attributes are converted to camelCase keys:

data-start-date    → startDate
data-end-date      → endDate
data-source        → source
data-custom-value  → customValue

EXAMPLE: AVAILABILITY ALTERNATIVES
----------------------------------
beforeDateSelectCallback: async (range) => {
  const result = await checkAvailability(range);

  if (!result.available) {
    picker.showMessage(`
      <div>Dates not available. Try these:</div>
      ${result.alternatives.map(alt => `
        <button data-action="custom"
                data-start-date="${alt.start}"
                data-end-date="${alt.end}"
                data-source="availability">
          ${alt.label}
        </button>
      `).join('')}
    `);
    return { action: 'restore', showInvalidRange: true };
  }

  return { action: 'accept' };
};

picker.addEventListener('custom-action', (e) => {
  const { startDate, endDate, source } = e.detail;

  if (source === 'availability' && startDate && endDate) {
    picker.selectedRanges = [{
      start: new Date(startDate),
      end: new Date(endDate)
    }];
    picker.hideMessage();
  }
});

EVENT BUBBLING
--------------
The custom-action event:
- Bubbles through the DOM
- Is composed (crosses Shadow DOM boundaries)
- Can be captured on the web component or any parent element

BACKWARD COMPATIBILITY
----------------------
The onClick callback on action buttons still works:

{
  action: 'custom',
  text: 'My Button',
  onClick: (picker) => {
    // This still fires after the event
  }
}

Event fires BEFORE onClick callback is invoked.

BEFOREDATESELECT CALLBACK
-------------------------
CRITICAL: JavaScript API ONLY
Validation/control BEFORE selection finalized.

const picker = new DateRangePicker(input, {
  beforeDateSelectCallback: (dateOrRange) => {
    // Return action object
    return {
      action: 'accept' | 'adjust' | 'restore' | 'clear',
      adjustedDate?: Date,           // For single mode
      adjustedStartDate?: Date,      // For range mode
      adjustedEndDate?: Date,        // For range mode
      message?: string               // Optional user message
    };
  }
});

RETURN ACTIONS
--------------
'accept' - Allow selection as-is
'adjust' - Modify the selection
'restore' - Revert to previous selection
'clear' - Clear selection entirely

SINGLE MODE VALIDATION
----------------------
Block weekends:

beforeDateSelectCallback: (date) => {
  const isWeekend = date.getDay() === 0 || date.getDay() === 6;

  if (isWeekend) {
    return {
      action: 'restore',
      message: 'Weekends not allowed'
    };
  }

  return { action: 'accept' };
}

Adjust to next business day:

beforeDateSelectCallback: (date) => {
  const day = date.getDay();

  if (day === 0) { // Sunday → Monday
    const adjusted = new Date(date);
    adjusted.setDate(date.getDate() + 1);
    return {
      action: 'adjust',
      adjustedDate: adjusted,
      message: 'Adjusted to Monday'
    };
  } else if (day === 6) { // Saturday → Monday
    const adjusted = new Date(date);
    adjusted.setDate(date.getDate() + 2);
    return {
      action: 'adjust',
      adjustedDate: adjusted,
      message: 'Adjusted to Monday'
    };
  }

  return { action: 'accept' };
}

Block past dates:

beforeDateSelectCallback: (date) => {
  const today = new Date();
  today.setHours(0, 0, 0, 0);

  if (date < today) {
    return {
      action: 'restore',
      message: 'Past dates not allowed'
    };
  }

  return { action: 'accept' };
}

RANGE MODE VALIDATION
---------------------
Minimum nights requirement:

beforeDateSelectCallback: (range) => {
  const nights = Math.floor(
    (range.end - range.start) / (1000 * 60 * 60 * 24)
  );

  if (nights < 2) {
    return {
      action: 'restore',
      message: 'Minimum 2 nights required'
    };
  }

  return { action: 'accept' };
}

Maximum nights limit:

beforeDateSelectCallback: (range) => {
  const nights = Math.floor(
    (range.end - range.start) / (1000 * 60 * 60 * 24)
  );

  if (nights > 7) {
    return {
      action: 'restore',
      message: 'Maximum 7 nights allowed'
    };
  }

  return { action: 'accept' };
}

Adjust end date to checkout day (Sunday):

beforeDateSelectCallback: (range) => {
  const endDay = range.end.getDay();

  if (endDay !== 0) { // Not Sunday
    const adjusted = new Date(range.end);
    const daysToSunday = 7 - endDay;
    adjusted.setDate(range.end.getDate() + daysToSunday);

    return {
      action: 'adjust',
      adjustedStartDate: range.start,
      adjustedEndDate: adjusted,
      message: 'Adjusted to Sunday checkout'
    };
  }

  return { action: 'accept' };
}

ASYNC VALIDATION
----------------
beforeDateSelectCallback supports async:

beforeDateSelectCallback: async (dateOrRange) => {
  // Show loading overlay automatically
  const response = await fetch('/api/check-availability', {
    method: 'POST',
    body: JSON.stringify({
      start: dateOrRange.start.toISOString(),
      end: dateOrRange.end.toISOString()
    })
  });

  const data = await response.json();

  if (data.available) {
    return { action: 'accept' };
  } else if (data.suggestedEnd) {
    return {
      action: 'adjust',
      adjustedStartDate: dateOrRange.start,
      adjustedEndDate: new Date(data.suggestedEnd),
      message: 'Adjusted to available dates'
    };
  } else {
    return {
      action: 'restore',
      message: 'Dates not available'
    };
  }
}

Loading overlay shown automatically during async.

COMBINING VALIDATIONS
---------------------
Multiple checks in one callback:

beforeDateSelectCallback: async (range) => {
  // 1. Check min/max nights
  const nights = Math.floor(
    (range.end - range.start) / (1000 * 60 * 60 * 24)
  );

  if (nights < 2) {
    return { action: 'restore', message: 'Min 2 nights' };
  }

  if (nights > 14) {
    return { action: 'restore', message: 'Max 14 nights' };
  }

  // 2. Check API availability
  const available = await checkAvailability(range);
  if (!available) {
    return { action: 'restore', message: 'Not available' };
  }

  // 3. Check user balance
  const cost = calculateCost(nights);
  if (cost > userBalance) {
    return { action: 'restore', message: 'Insufficient funds' };
  }

  return { action: 'accept' };
}

EXECUTION ORDER
---------------
For a selection to complete:

1. Local validation (disabled dates, min/max)
2. beforeDateSelectCallback callback (if provided)
3. Selection finalized
4. date-select event fires

If any step fails, selection reverts.

USE CASES
---------
Block invalid selections:
- Blackout dates
- Unauthorized dates
- Past dates
- Invalid ranges

Adjust selections:
- Round to business days
- Snap to available dates
- Enforce checkout days
- Correct time zones

API validation:
- Check availability
- Verify permissions
- Validate pricing
- Confirm capacity

Business rules:
- Minimum stay
- Maximum advance booking
- Lead time requirements
- Special event rules

SHOWING MESSAGES
----------------
Display validation messages:

const picker = new DateRangePicker(input, {
  beforeDateSelectCallback: async (range) => {
    const result = await validate(range);

    if (!result.valid) {
      showToast(result.message, 'error');
      return { action: 'restore', message: result.message };
    }

    return { action: 'accept' };
  }
});

picker.addEventListener('date-select', (event) => {
  showToast('Dates selected', 'success');
});

ERROR HANDLING
--------------
Handle async errors:

beforeDateSelectCallback: async (range) => {
  try {
    const available = await checkAvailability(range);
    return available
      ? { action: 'accept' }
      : { action: 'restore', message: 'Not available' };
  } catch (error) {
    console.error('Validation error:', error);
    showError('Unable to validate dates');
    return { action: 'restore' };
  }
}

DEBUGGING
---------
Log all validation calls:

beforeDateSelectCallback: (dateOrRange) => {
  console.log('Validating:', dateOrRange);

  const result = performValidation(dateOrRange);

  console.log('Result:', result);

  return result;
}

Track performance:

beforeDateSelectCallback: async (range) => {
  const start = performance.now();

  const result = await validate(range);

  const duration = performance.now() - start;
  console.log('Validation took:', duration, 'ms');

  return result;
}

BEST PRACTICES
--------------
1. Keep validation fast
   - Cache API responses
   - Debounce expensive checks
   - Pre-load validation data

2. Provide clear feedback
   - Use descriptive messages
   - Show why selection failed
   - Suggest alternatives

3. Handle errors gracefully
   - Try/catch async code
   - Fallback to safe defaults
   - Log errors for debugging

4. Test edge cases
   - Network failures
   - Timeout scenarios
   - Concurrent selections
   - Boundary conditions

5. Use appropriate actions
   - 'restore' for hard rejections
   - 'adjust' for auto-corrections
   - 'clear' for complete resets
   - 'accept' when valid

WEB COMPONENT LIMITATIONS
--------------------------
beforeDateSelectCallback is JavaScript API ONLY.

✅ Works:
const picker = new DateRangePicker(input, {
  beforeDateSelectCallback: (date) => { ... }
});

❌ Doesn't work:
<web-daterangepicker
  before-date-select="...">  <!-- Not an attribute -->
</web-daterangepicker>

For web component, validate in event listener instead:

picker.addEventListener('date-select', (event) => {
  const { date } = event.detail;

  if (!isValid(date)) {
    event.preventDefault();  // Doesn't work for validation
    picker.clearSelection();
    showError('Invalid date');
  }
});

NOTE: Event-based validation happens AFTER selection.
Use JavaScript API for BEFORE validation.

BEFOREMONTHCHANGEDCALLBACK
===========================
CRITICAL: JavaScript API ONLY (Web Component Property)
Performance optimization for bulk metadata loading.

OVERVIEW
--------
beforeMonthChangedCallback is called BEFORE month navigation occurs.
Allows you to:
- Load bulk metadata for all visible dates in ONE API call
- Block navigation to unavailable months
- Show loading overlay during async operations

PERFORMANCE BENEFIT
-------------------
WITHOUT beforeMonthChangedCallback:
- User navigates to November
- Calendar renders 35-42 days
- getDateMetadataCallback called 35-42 times
- Result: 35-42 API calls or lookups

WITH beforeMonthChangedCallback:
- User navigates to November
- beforeMonthChangedCallback called ONCE with date range
- 1 API call fetches all 35-42 days
- Metadata cached and applied to all days
- Result: 1 API call

CALLBACK SIGNATURE
------------------
JavaScript API:

const picker = new DateRangePicker(input, {
  beforeMonthChangedCallback: async (context) => {
    // context: { year, month, monthIndex, firstVisibleDate, lastVisibleDate }
    // Returns: { action: 'accept' | 'block', metadata?, message? }
  }
});

Web Component (Property):

const picker = document.querySelector('web-daterangepicker');
picker.beforeMonthChangedCallback = async (context) => {
  // Same as above
};

CONTEXT PARAMETER
-----------------
{
  year: number,              // 2025
  month: number,             // 0-11 (January = 0)
  monthIndex: number,        // Which visible month column (0, 1, 2...)
  firstVisibleDate: Date,    // First date in calendar grid (may be prev month)
  lastVisibleDate: Date      // Last date in calendar grid (may be next month)
}

DATE RANGE CALCULATION
----------------------
Single Month Mode:
- firstVisibleDate/lastVisibleDate span ~42 days (6 weeks around the target month)
- Example: November calendar shows ~Oct 26 to Dec 6

Unified Navigation Mode:
- firstVisibleDate/lastVisibleDate span ALL visible months
- Example: 2×3 grid showing Jan-Jun = ~180 days (late Dec to mid-Jul)
- Allows bulk loading metadata for entire visible range in one API call
- Significantly reduces API calls for multi-month displays

RETURN ACTIONS
--------------
'accept' - Allow navigation, proceed to new month
'block' - Prevent navigation, stay on current month

RETURN STRUCTURE
----------------
{
  action: 'accept' | 'block',
  metadata?: Map<string, DateInfo>,  // YYYY-MM-DD -> DateInfo
  message?: string                    // Optional (for block action)
}

HOTEL AVAILABILITY EXAMPLE
---------------------------
Load pricing and availability for entire month:

beforeMonthChangedCallback: async ({ firstVisibleDate, lastVisibleDate }) => {
  // Single API call for entire visible range
  const response = await fetch('/api/hotel/availability', {
    method: 'POST',
    body: JSON.stringify({
      startDate: firstVisibleDate.toISOString().split('T')[0],
      endDate: lastVisibleDate.toISOString().split('T')[0],
      roomType: 'deluxe'
    })
  });

  const availability = await response.json();
  // [
  //   { date: "2025-11-01", available: 5, price: 150 },
  //   { date: "2025-11-02", available: 0, price: 150 },
  //   ...
  // ]

  // Build metadata map
  const metadata = new Map();
  availability.forEach(day => {
    metadata.set(day.date, {
      isDisabled: day.available === 0,
      badgeText: day.available === 0 ? '✕' : `$${day.price}`,
      badgeClass: day.available === 0 ? 'sold-out' : 'available',
      dayTooltip: day.available === 0
        ? 'Sold out'
        : `${day.available} rooms available at $${day.price}/night`
    });
  });

  return {
    action: 'accept',
    metadata: metadata
  };
}

BLOCK NAVIGATION EXAMPLE
-------------------------
Prevent navigation to months without data:

beforeMonthChangedCallback: async ({ year, month }) => {
  try {
    const response = await fetch(`/api/check-period/${year}/${month + 1}`);
    const { dataReady } = await response.json();

    if (!dataReady) {
      return {
        action: 'block',
        message: 'Data not yet available for this period'
      };
    }

    return { action: 'accept' };
  } catch (error) {
    console.error('Failed to check period:', error);
    return {
      action: 'block',
      message: 'Unable to load data for this period'
    };
  }
}

LOADING OVERLAY
---------------
Loading overlay shown AUTOMATICALLY during async operations.
No manual control needed.

METADATA PRIORITY
-----------------
When rendering dates, priority is:
1. Bulk metadata cache (from beforeMonthChangedCallback)
2. getDateMetadataCallback (per-day callback)
3. specialDates (static array)

Bulk metadata has HIGHEST priority.

CACHE BEHAVIOR
--------------
- Cache is REPLACED on each successful navigation
- Navigating to September → cache updated
- Navigating to October → cache updated
- Navigating BACK to September → callback called AGAIN, cache updated

No automatic caching - callback is called every time.
If you want caching, implement it IN your callback.

COMBINING WITH getDateMetadataCallback
---------------------------------------
You can use BOTH callbacks together:

beforeMonthChangedCallback: async ({ firstVisibleDate, lastVisibleDate }) => {
  // Bulk load pricing
  const metadata = new Map();
  // ... load pricing for all dates
  return { action: 'accept', metadata };
},

getDateMetadataCallback: (date) => {
  // Override specific dates with special conditions
  if (isHoliday(date)) {
    return {
      badgeText: '🎉',
      badgeClass: 'holiday',
      isDisabled: true
    };
  }
  return null; // Use bulk cache
}

Priority: getDateMetadataCallback wins if it returns non-null.

BEST PRACTICES
--------------
1. Use for expensive operations
   - API calls to fetch pricing/availability
   - Database lookups
   - Complex calculations

2. Keep it fast
   - Single API call, not multiple
   - Use Promise.all for parallel requests
   - Cache responses in your app if appropriate

3. Handle errors gracefully
   - Try/catch async operations
   - Return 'block' on error to be safe
   - Log errors for debugging

4. Provide clear messages
   - Use 'message' field with 'block' action
   - Help users understand why navigation was blocked

5. Build metadata efficiently
   - Use Map for O(1) lookups
   - Format date keys as YYYY-MM-DD
   - Only include dates that need metadata

EXAMPLE: EVENT CALENDAR
------------------------
Color-code days with events:

beforeMonthChangedCallback: async ({ firstVisibleDate, lastVisibleDate }) => {
  const events = await fetchEvents(firstVisibleDate, lastVisibleDate);

  const metadata = new Map();
  events.forEach(event => {
    metadata.set(event.date, {
      badgeText: event.type === 'conference' ? '🎤' : '💻',
      dayClass: `event-${event.type}`,
      dayTooltip: event.title
    });
  });

  return { action: 'accept', metadata };
}

LIMITATIONS
-----------
1. JavaScript API or Web Component Property ONLY
   Cannot be set as HTML attribute

2. Called every navigation
   No built-in caching - implement in your callback if needed

3. Blocks UI during async
   Keep operations fast (< 1 second recommended)

4. No cancellation
   Once triggered, callback runs to completion
