📱 Mobile & Full-Screen

On phones the calendar opens as an edge-to-edge full-screen sheet instead of a floating popover — big touch targets, a close header, and the months stacked vertically. On tablets it opens as a centered modal, and on desktop it stays a floating popover. These demos cover how the presentation is chosen, the soft-keyboard policy, and the header options.

1 · mobile-presentation — the device ladder

A floating picker adapts to the device automatically. The classification comes from @keenmate/web-components-core and is capability-based and orientation-robust — it uses the shorter viewport side, so a landscape phone still reads as a phone.

DeviceDetected whenPresentation
Phonetouch-primary & shorter side < 600pxfullscreen (edge-to-edge)
Tablettouch-primary & shorter side ≥ 600pxmodal (centered dialog)
Desktopfine pointer (mouse), any widthfloating (anchored popover)
  • auto (default) — the ladder above.
  • floating / modal / fullscreen — force that presentation on any device (handy for previewing the phone sheet on desktop, which is what the toggles on this page do).

Because full-screen is usually a phone-only look, every demo defaults to auto and offers a Preview as full-screen toggle so you can see the overlay here on desktop. Close the sheet with the ✕ in its header, Escape, or the phone Back gesture.

<!-- auto (default): floating on desktop, modal on tablets, fullscreen on phones --> <web-daterangepicker></web-daterangepicker> <!-- force one presentation everywhere --> <web-daterangepicker mobile-presentation="floating"></web-daterangepicker> <web-daterangepicker mobile-presentation="fullscreen"></web-daterangepicker>

2 · fullscreen-autofocus — soft keyboard on phones

By default the keyboard stays closed when the full-screen sheet opens — it shows the calendar first, so you tap dates and the bottom action row stays reachable. Set fullscreen-autofocus to focus the input on open instead (pops the keyboard for type-to-fill, like a native picker).

Both pickers use mobile-presentation="auto": a floating popover here on desktop, a full-screen sheet on a phone — where the keyboard difference actually shows. Tick Preview as full-screen to see the overlay on desktop.

<!-- default: keyboard stays closed, calendar visible --> <web-daterangepicker></web-daterangepicker> <!-- opt in to focus the input + soft keyboard on open --> <web-daterangepicker fullscreen-autofocus></web-daterangepicker>

3 · fullscreen-input — type dates in the header

In the full-screen sheet the trigger field normally sits behind the overlay, so there's nothing to type into. fullscreen-input moves the real input up into the sheet header — visible, above the calendar, and wired to the same mask. It gets inputmode="numeric", so phones show a digits-only keypad: you type 08192026 and the mask fills in the separators (08/19/2026). You never need the / or . key a numeric keypad hides — the component owns them.

Pair it with fullscreen-autofocus to pop that keypad on open for a type-first flow, or leave autofocus off and let users tap the header field when they want to type. The header input takes over the row, so it's shown instead of fullscreen-title.

<!-- typeable input in the full-screen header, numeric keypad + mask --> <web-daterangepicker fullscreen-input></web-daterangepicker> <!-- type-first: also pop the keypad on open --> <web-daterangepicker fullscreen-input fullscreen-autofocus></web-daterangepicker>

4 · fullscreen-title — header heading

The full-screen header shows just a close (✕) button by default. Add fullscreen-title for a heading beside it — useful to label what the user is picking.

<web-daterangepicker fullscreen-title="Choose your dates"></web-daterangepicker>

5 · Forcing a presentation

Set mobile-presentation to a concrete value to override the device ladder on any device — for a deliberate design choice or to inspect the phone/tablet UI on a desktop.

Phone detection needs a viewport meta: your page must include <meta name="viewport" content="width=device-width"> — without it a mobile browser lays out at ~980px and the picker classifies the phone as a tablet (modal instead of full-screen).
